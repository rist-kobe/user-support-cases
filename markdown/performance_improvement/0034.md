# 支援事例 No.34

## 種別

性能改善

## 課題・問題点

(1) 計算性能の分析方法と改善方法を知りたい
(2) 現状の通信方法に改善の余地があるか知りたい
コード構造の改善

## 分類

性能分析および単体性能改善

## 支援内容

性能分析によりホットスポットは、計算ループ内の if 文と、分散した小配列へのアクセスと判明した。一方、通信はボトルネックではなかった。そこで、最適化方法として、if 文のループ内からの移動と、小配列のマージを提示した。

## 支援結果

性能分析方法・改善方法を伝え、最適化した結果、192ノード、8スレッド／ノードで実行速度が2.3倍に向上した。

## 支援タグ

コード構造の改善

## 技術タグ

Communication, OpenMP, PerformanceAnalysis

| 性能改善率 | - |
