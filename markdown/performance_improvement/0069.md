# 支援事例 No.69

## 種別

性能改善

## 課題・問題点

１プロセスの使用メモリが多く、ノード内のコアを使ったフラットMPIでの実行が困難なプログラムである。そのため、MPIとノード内自動並列を組み合わせたハイブリッド並列で実装している。しかし、自動並列でのノード内並列から、更なる並列化が可能なのか知りたい。
コード構造の改善

## 分類

性能改善

## 支援内容

性能評価ツール(fipp)で高コスト部分を特定し、順次性能改善方法を提示した。
・反復ループ内で配列のゼロクリアがホットスポットと断定。ループ反復時に更新されない部分はクリアしないようにすることで計算時間を短縮した。
・距離の判定で、平方根の計算コストが大きいと断定。平方根を求めずに判定する方法を提案した。
・自動並列化できない５ループについて、OpenMP指示行による並列化を実施した。

## 支援結果

ノード内のスレッド数を変化させた時の計算時間は以下の通り。
・1スレッド　…　5,700秒
・2スレッド　…　3,291秒
・4スレッド　…　2,117秒
・8スレッド　…　1,693秒
オリジナル8スレッド利用時の5,861秒と比べて3.46倍高速となった。
この支援を受け依頼者は、これからのコード開発において同じような高度化を適用することになった。
