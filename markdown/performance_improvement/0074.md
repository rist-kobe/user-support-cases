# 支援事例 No.74

## 種別

性能改善

## 課題・問題点

「富岳」において、並列前処理が極端に遅い（400ノード利用時、「京」では10分程度で完了する計算が、「富岳」では5時間以上かかる）原因と改善法の調査
I/O・メモリ最適化

## 分類

性能改善

## 支援内容

大容量の計算ログ用、あるいは、多数のデバッグ用出力を全プロセスから単一の標準出力に行っていたために出力リソースの奪い合いが生じ、遅延が発生していた。これをprocess 0のみで出力、あるいは出力しないように変更した。

## 支援結果

計算ログ用の出力をprocess 0だけが行うように修正した結果、修正前では5時間以上要していた計算が5分以内で終了するようになった。また、修正前は不可能だった1000ノード以上を使った計算も同様に10分以内で終了するようになった。

## 支援タグ

I/O・メモリ最適化

## 技術タグ

IO, Memory
