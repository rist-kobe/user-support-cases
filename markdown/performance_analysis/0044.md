# 支援事例 No.44

## 種別

性能分析

## 課題・問題点

分散型の深層強化学習手法である”Ape-X DQN”を使用した自作スクリプトについて、京大スパコンのシステムBの10並列では約2時間で終了した計算が、「富岳」の30並列では大幅に時間が増大したので原因を調査してほしい。
コードについて、機械学習にはTensorFlow、並列化にはRayを使用している（並列化はCPUのみを使用）。
ソフトウェア評価
AI・機械学習

## 分類

性能分析

## 支援内容

測定対象として、TensorFlowとRayを組み込んだsingularityコンテナを作成し、ユーザ提供のデータを用いて調査を行った。 「富岳」計算ノード以外にもサテライト富岳を用いて性能比較を行った。 並列数を変えた計算を行い、並列数を増加させたときに、実行時間の増大が再現できるかを調査した。 time.time関数を用いてスクリプトの区間ごとの経過時間を計測し、スクリプト中の高負荷箇所を特定した。

## 支援結果

「富岳」計算ノードとサテライト富岳で性能調査を行った結果、サテライト富岳のほうが、「富岳」計算ノードより3-4倍高速であったため、本計算にはサテライト富岳の方が適していると判断した。
サテライト富岳で、複数のTensorFlowのバージョン間(2.10, 2.14, 2.19)で性能比較を行った結果、TensorFlow 2.10が最速であることがわかった。
またサテライト富岳で、並列数を変えて性能を比較したところ、ユーザー提供のデータでは、16並列で性能が飽和するものの、並列数をそれ以上増やしても実行時間が長くなる現象は見られなかったため、ジョブスクリプトの設定など、実行時の設定などに問題があったのかもしれない。
RISTが作成したsingularityコンテナとそれを作成するために使用したsingularity定義ファイル、サテライト富岳用のジョブスクリプトを依頼者に提供した。
