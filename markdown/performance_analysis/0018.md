# 支援事例 No.18

## 種別

性能分析

## 課題・問題点

性能分析、分析手法およびスケーラビリティについて
ソフトウェア評価

## 分類

単体性能および並列性能の分析

## 支援内容

「京」上での実行時のメモリサイズが、1ノードあたり14GBを上回っており、簡易プロファイラ、詳細プロファイラを実行するも、共にメモリ不足で実行できず、性能を分析することができなかった。このため、RISTが保有する評価用の富士通社製FX10（24ノードでの仮実行）を用いて、性能の大体の傾向を分析し、ボトルネックとなっているループを特定した。当該ループに対して、コンパイラ指示行による最適化を試みたが、回転数がわずが6であることもあり、性能改善に至らなかった。また、並列性能については、データ500のケースでスーパーリニアとなっていることが判明し報告した。

## 支援結果

プログラムは、各ノードで同じデータを保持する仕様であるため、使用メモリ量を削減するためには、プログラムのデータ構造の変更に着手しなければならない。本分析結果を基に、使用メモリ量の削減とボトルネックとなっているループ構造の変更とを利用者が検討することになった。スケーラビリティについては、今後調査する予定。
